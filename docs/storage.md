# 数据与存储

## 数据位置

项目管理的运行数据固定写在应用目录下：开发及 `npm start` 使用项目根目录，安装版使用可执行文件所在目录。启动命令的工作目录不会改变存储根目录。

| 路径        | 内容                                              |
| ----------- | ------------------------------------------------- |
| `database/` | 设置库、用户内容库、公共缓存及 SQLite WAL/SHM     |
| `file/`     | 按账号和资源管理的图片、视频与普通附件缓存        |
| `backups/`  | 调用内容库备份接口后生成的在线备份                |
| `log/`      | 主进程、错误及 Electron 运行日志                  |
| `updates/`  | 更新安装包和下载中的临时文件                      |
| `.runtime/` | Electron 用户数据、会话缓存、临时目录和崩溃信息等 |
| `.cache/`   | 开发工具和依赖下载缓存                            |

应用目录必须可写。旧位置的数据不会自动迁移或删除；移动程序需要同时考虑运行数据。用户主动另存为或拖出附件产生的副本写到用户选择的目标，不属于默认缓存目录。

## 数据库

数据库只由 Electron 主进程打开，渲染页面通过受控 preload 调用。运行库为 `better-sqlite3-multiple-ciphers`，连接启用 WAL、外键和锁等待。

| 文件              | 保存内容                                                                         | 保护方式                                                    |
| ----------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `settings.sqlite` | 登录偏好、Debug 开关、日志等级、OCR 后端记录、加密账号及会话                     | 设置库本身未加密；账号身份和 JWT 使用系统安全存储加密后写入 |
| `<uid>.sqlite`    | 用户资料、联系人缓存、会话、消息、引用、未读与删除状态、表情、附件索引及播放进度 | 使用后端 `clientSqlPassword` 打开加密数据库                 |
| `public.sqlite`   | 按图片 SHA-256 共享的 OCR 原始文字及坐标                                         | 明文缓存，应用访问仍要求有效授权                            |

启动阶段只打开设置库；用户内容库在真实授权及确认进入后打开，公共 OCR 库在首次需要时打开。退出账号关闭内容库，不创建访客库。

内容库按后端 UID 隔离，不按密码或用户输入账号生成身份。切换账号时旧任务、窗口及读取权限失效；页面不能自行指定另一个账号的数据库。

## 密钥与内容范围

内容库密钥由后端登录及身份校验流程提供，只保留在主进程会话中，不保存到持久化登录记录，不暴露给页面。保存的 JWT 还需要后端验证，不能仅凭本地解密成功打开内容库。

系统加密会话不适合直接复制到其他机器或系统用户使用。附件文件、日志和公共 OCR 缓存不因为内容库加密而自动加密，也不应将本地数据加密描述为聊天端到端加密。

## 附件与文件记录

媒体正文保存资源元数据，本地副本位于 `file/`，数据库记录对应索引。资源读取校验账号、会话、消息和受控路径，下载先写临时文件，完成后再作为有效缓存使用。

发送源文件、已下载附件和存储层文件记录是不同对象。移除草稿或存储层文件记录不删除原文件；清空会话可调度其受管理缓存的清理，并检查是否仍被其他记录引用。文件记录的查询和删除接口不等同于当前界面提供了独立文件管理器。

本机上传来源绑定当前安装。复制内容库到另一台设备不会自动授予对原始文件路径的访问或继续上传资格。

## 备份

主进程通过 `database:backup` 和主窗口桥接的 `backupDatabase()` 提供内容库在线备份能力，在 `backups/` 生成带随机标识的 `.sqlite` 文件，不覆盖已有备份。当前页面没有调用该能力的菜单或按钮，因此它属于已实现的底层接口，不是用户可直接点击的设置项。

在线备份用于取得一致的数据库副本，避免仅复制运行中的主文件而遗漏 WAL 数据。调用仍须通过当前账号和来源窗口校验。

备份只覆盖当前用户内容库，不包含：

- `settings.sqlite` 中的账号会话和全局偏好。
- `public.sqlite` 中的共享 OCR 缓存。
- `file/` 中的附件字节及用户原始文件。
- 日志、更新安装包和其他运行缓存。

备份文件应作为敏感用户数据保管。当前没有图形化恢复入口或跨版本数据库迁移流程；恢复需确认目标版本结构与密钥条件，并在关闭相关连接后由维护人员处理。备份成功不等于已经验证任意版本间的恢复兼容性。

## 表结构与升级

代码按当前表结构创建所需表与索引，不维护通用的版本迁移体系。发现不兼容结构时可能拒绝打开并提示保留原库。安装更新不会自动解决任意旧数据库结构的不兼容。

当前安装脚本存在缺失，不能承诺安装、覆盖升级或卸载一定保留程序旁数据，详见 [Windows 发布与更新](windows-updates.md)。

## 日志

| 文件               | 用途                       |
| ------------------ | -------------------------- |
| `log/main.log`     | 主进程业务、网络及运行记录 |
| `log/error.log`    | 独立错误记录               |
| `log/electron.log` | Electron 运行日志          |

主日志和错误日志分别设置 10 MiB 轮转上限，旧文件使用对应 `.old.log` 名称。设置页提供 `error`、`warn`、`info` 等级，保存后立即影响主进程日志阈值。

日志层对凭据等敏感字段执行脱敏。诊断信息仍可能含业务标识和环境信息，提供问题材料时应按实际内容确认范围。
