# 消息正文缓存

## 虚拟列表

聊天区使用 `BubbleList` 虚拟列表，按消息 ID 保持稳定行身份，仅渲染可见区域及缓冲区。虚拟渲染与数据库分页分开处理，不一次性把全部历史读入页面。

每个会话以当前视口为中心设置 300 条正文的目标保留范围；可见范围本身不会被裁掉。未确认和失败待重试消息保留完整内容，避免影响恢复发送。工作台另有最多 8 个会话的缓存数量限制。

## 正文回收

远离视口且已确认的消息在原位置替换为轻量占位，保留消息身份、时间、状态、引用关系和行高。列表位置不被删除，滚动条不会因为回收正文直接丢失对应行。

实际行高包含消息间距与时间分隔；未渲染行使用虚拟器估算。宽度变化时先保留占位高度，重新读取正文后再测量，并用可见消息及像素偏移校准位置。用户继续滚动或发起新定位后停止旧的校正。

## 按需回读

向上和向下滚动都会提前读取临近正文，单批最多 50 条。已浏览区域按原消息 ID 精确查询 SQLite；尚未浏览的更早历史继续通过时间和 ID 游标加载。

异步回读只替换请求发出时的原占位对象，不覆盖期间到达的消息确认、撤回或删除结果。读取失败保留高度并提供重试入口。

桌面通过 `database:read-message-batch` 读取当前授权账号和指定会话的本地记录，不因正文回读请求远端。浏览器模式使用内存数据源，释放显示正文不会删除其内存数据源。

## 适用范围

该策略控制正文和展示资源的保留范围，轻量消息身份及高度仍会随浏览量增长，不能描述为整个列表内存恒定。独立历史搜索窗口使用自己的分页展示，不套用聊天区的整套缓存列表。
